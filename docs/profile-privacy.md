# 個人頁可見性

新帳號預設不公開。登入頁先說明資料用途；使用者必須在帳號設定勾選「我同意公開個人頁」並儲存，才會公開名稱、代號、頭像、追蹤單位及即將參加的活動。Email 不公開。公開設定也涵蓋之後新增及綁定合併的追蹤與活動；帳號設定持續顯示目前狀態及合併說明。匿名統計仍計入追蹤及參加總人數。私人貢獻者在貢獻榜匿名顯示。

## 啟用與相容性

部署此版後重新啟動 auth server 即生效，不需要手動更新正式資料庫。初始化可重複執行：

- 全新資料庫的 `profile_public` 欄位預設為 `0`。
- 既有資料庫已存在該欄位時，保留每個帳號原本的值，包括公開選擇；不批次改寫。SQLite 的舊 `DEFAULT 1` 也無需重建資料表，因所有 OAuth 新帳號共用的 INSERT 明確寫入 `0`。
- 若升級自尚無可見性欄位的歷史資料庫，新增欄位時保留當時既有個人頁公開的行為；之後建立的帳號仍明確寫入 `0`。
- 再次登入、綁定及合併不改變目前帳號的可見性選擇。

因此既有公開帳號仍保持公開；這次修改不宣稱已取得舊帳號的重新同意。使用者可以在帳號設定改為不公開。

## 驗證

`python -m unittest discover -s tests -p test_auth_server.py` 使用臨時 SQLite 與假的 OAuth 回應，覆蓋三種 OAuth 新帳號、兩種舊 schema、重複初始化、公開與關閉、合併、私人頁與已快取頭像對訪客及其他帳號的存取限制。未使用真實帳號或正式資料庫。
